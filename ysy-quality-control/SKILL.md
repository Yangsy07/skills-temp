# ysy-quality-control（工程建设质量管控 · 材料判定与整改闭环）

## 1. 本技能做什么

面向**公路水运工程施工阶段**的质量管控。监管链条：材料进场报验 → 自动判定 → 不合格拦截 → 问题分级 → 整改通知 → 复查销号 → 工序验收放行。核心痛点是**未检先用屡禁不止、不合格材料退场不彻底、整改时限无人盯**。

本技能给出该场景的业务口径与交付验收标准，供产出需求文档、解决方案、原型、核心功能与演示清单时对照。

## 2. 何时使用

- 用户要求做「工程建设质量管控」场景的整套交付物；
- 需要该场景的材料判定、问题分级、工序放行、合格率红线等规则口径与验收基线。

## 3. 需求调研（先做，再定方案）

需求调研是产出需求文档前的主动过程，不是一次问答。按四步推进，每步达成即进入下一步：

1. **角色与场景梳理**——列出本场景全部角色（见「场景定位」）与每个角色的业务动作。
   完成判据：每个角色至少 1 个动作，动作连成业务闭环。
2. **痛点收集**——从业务现状归纳真实痛点（未检先用屡禁不止、不合格材料退场不彻底、整改时限无人盯），每条写清「现象 → 后果」。
   完成判据：每条痛点至少对应 1 条功能需求。
3. **规则口径确认**——把本场景判定规则逐条钉死（见「规则体系」：材料判定、未检先用红线、问题分级（重大0/较大3/一般7）、工序放行、合格率 90%），阈值、时限、边界两侧都明确。
   完成判据：每条规则可判定、可核验，边界两侧（恰好 N / 刚超过 N）都有结果。
4. **需求来源追溯**——每条需求与规则追到来源：业务痛点、引用标准号（写明标准号与条款号）、或题面给定值；自定口径显式标注。
   完成判据：不存在无来源的需求；不编造业务事实与标准号。
   需求分析内容框架与分层追问见 `ysy-solution-builder` §11、§12；开工与收尾门禁、生成前置必答需求调研见 §4、§12（题目口径与预设不同时以用户口径为准）。

## 4. 场景定位

- 系统名：工程质量管控平台
- 角色：施工质量员 / 施工班组 / 监理工程师 / 检测单位 / 项目负责人 / 质量监督
- 业务闭环：报验登记 → 自动判定合格与否 → 不合格拦截并生成整改/退场事项 → 按级别倒计时 → 复检放行或退场销号 → 驾驶舱与合格率联动
- 特色能力：**「未检先用」独立红线**，与材料合格判定、问题分级共同构成三道拦截

## 5. 规则体系（口径唯一来源）

| # | 规则项 | 对象 | 判定条件 | 处置 |
|---|---|---|---|---|
| 1 | 材料判定 | 钢筋 / 混凝土 / 水泥 | 实测值 ≥ 标准库标准值 → 合格，否则不合格 | 不合格 → 禁止使用 + 退场 |
| 2 | 材料判定 | 沥青混合料 AC-13 | 实测值 ≥ 标准值 60（%）→ 合格 | 不合格 → 供应商质量扣分并退场 |
| 3 | 问题分级 | **未检先用** | 未取得检测结论即进场使用 → **重大** | 立即停工整改 + 上报专项处理 |
| 4 | 问题分级 | 检测不合格 | 检测判定不合格 → **较大** | 3 天内整改，逾期升级质监 |
| 5 | 问题分级 | 其他偏差 | 非否决项偏差 → **一般** | 7 天内整改，逾期升级监理 |
| 6 | 整改时限 | 重大 / 较大 / 一般 | 重大立即（**0 天**）、较大 **3 天**、一般 **7 天**；届满前 1 天预警 | 自动生成整改通知单并按级倒计时 |
| 7 | 工序放行 | 工序验收 | 结论为「**合格 / 复检合格**」方可放行；未验先用直接停工 | 禁止放行 → 补验收流程 |
| 8 | 合格率红线 | 月度抽检合格率 | 合格率 ≥ **90 %** 为达标 | 低于红线触发质量专项分析 |

**关键常量**：`整改时限 重大=0、较大=3、一般=7`；`合格率红线=0.9`；`可放行结论=['合格','复检合格']`；`预警提前天数=1`。
标准库（3 项）：`钢筋HRB400 = 400 MPa`、`沥青混合料AC-13 = 60 %`、`路基96区压实度 = 96`。

## 6. 系统设计

### 6.1 原型页面（6 个）

| # | 页面 | 职责 |
|---|---|---|
| 1 | 质量驾驶舱 | 报验批次 / 已放行 / 不合格拦截 / 待处置事项 / 重大事项 / 合格率 |
| 2 | 材料报验与判定 | 进场报验 → 自动检测判定 → 不合格拦截并生成整改/退场事项 |
| 3 | 问题整改与放行 | 按级别时限倒计时 → 退场／复检放行 → 复查销号闭环 |
| 4 | 报验与验收台账 | 全量报验记录：实测值、标准值、判定、级别、状态 |
| 5 | 规则预警中心 | 规则库批量跑批：不合格拦截 / 未检先用 / 未验收放行 / 整改超期 |
| 6 | 统计分析 | 供应商合格率对比、不合格拦截与超期整改预警 |

**驾驶舱卡片**（6 张）：报验批次 / 已放行 / 不合格拦截 / **待处置事项** / 重大事项 / 报验合格率(%)。

**表单字段**：供应商·供货单位 / 材料名称（决定标准值）/ 规格·批次号 / 实测值（MPa 或 %）/ **是否未检先用**（是·否）。

**闭环演示路径**：材料报验（钢筋HRB400 实测填 `380` 复现不合格拦截，填 `420` 复现合格放行）→ 问题整改与放行出现新事项与整改倒计时 → 点「退场并销号」或「复检放行」→ 回质量驾驶舱看数字联动、统计分析合格率刷新。


**原型设计准则**：原型是回答设计问题的可运行演示，详见 `ysy-solution-builder` 的「原型设计准则」一节。本场景原型完成判据：6 页可点通闭环、共享数组联动正确、每条功能需求有对应页面。

## 9. 业务设计要点

1. **「未检先用」优先级最高**：它是独立布尔字段，判定顺序必须在「材料是否合格」之前。若先按实测值判合格再看了布尔位，会把「合格但未检先用」错判为一般而非重大——性质完全不同（重大 → 立即停工 + 上报专项）。
2. **可放行不等于「合格」**：`可放行结论 = ['合格','复检合格']`，复检合格同样放行。用 `结论 === '合格'` 会把复检合格的批次挡在门外。
3. **重大级别时限为 0 天**：倒计时应显示「立即停工整改」而非负数天数。
4. **合格率红线 90 % 含等号**：`合格率 ≥ 0.9` 达标，恰好 90 % 不触发专项分析。
5. **标准库决定阈值与单位**：材料名称一变，标准值与量纲（MPa / %）都要跟着换，表单里的实测值提示也应同步。
6. **标准库缺项要有兜底**：材料不在标准库时不得抛错，应转人工判定。
