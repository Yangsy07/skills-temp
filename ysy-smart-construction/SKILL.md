# ysy-smart-construction（智慧工程建设 · 施工现场安全管理）

## 1. 本技能做什么

面向公路 / 市政**施工现场**的一体化管理。监管链条覆盖「人（实名人员 / 特种作业资质）— 机（机械维保）— 环（安全隐患巡查）— 进度（计划偏差）」，核心痛点是：**隐患靠纸质台账、整改靠人工催办、资质与维保到期无人预警**。

本技能给出该场景的业务口径与交付验收标准，供产出需求文档、解决方案、原型、核心功能与演示清单时对照。

## 2. 何时使用

- 用户要求做「施工现场安全管理」场景的整套交付物；
- 需要该场景的隐患分级、整改时限、资质预警等规则口径与验收基线。

## 3. 需求调研（先做，再定方案）

需求调研是产出需求文档前的主动过程，不是一次问答。按四步推进，每步达成即进入下一步：

1. **角色与场景梳理**——列出本场景全部角色（见「场景定位」）与每个角色的业务动作。
   完成判据：每个角色至少 1 个动作，动作连成业务闭环。
2. **痛点收集**——固定 3 条，每条写成「现象 → 后果」：
   1. 隐患记录靠纸质台账、状态靠人工统计 → 隐患底数不清，超期无人知，销号率无法计算
   2. 整改靠电话与现场口头催办 → 催办无留痕、责任难追溯，整改闭环率低
   3. 特种作业证件与机械维保到期无人预警 → 无证上岗与带病作业风险，安全检查被扣分
   完成判据：每条痛点至少对应 1 条功能需求。
3. **规则口径确认**——把本场景判定规则逐条钉死（见「规则体系」：**问题分类**（结构安全类 / 防护设施类 / 文明施工类）→ **风险分级**（重大 0 时限 / 较大 12h / 一般 24h）、证件 30 天、机械 7 天、进度 15%），阈值、时限、边界两侧都明确。
   完成判据：每条规则可判定、可核验，边界两侧（恰好 N / 刚超过 N）都有结果。
4. **需求来源追溯**——每条需求与规则追到来源：业务痛点、引用标准号（写明标准号与条款号）、或题面给定值；自定口径显式标注。
   完成判据：不存在无来源的需求；不编造业务事实与标准号。
   需求分析内容框架与分层追问见 `ysy-solution-builder` §11、§12；开工与收尾门禁、生成前置必答需求调研见 §4、§12（题目口径与预设不同时以用户口径为准）。

## 4. 场景定位

- 系统名：智慧工程项目管理平台
- 角色：项目负责人 / 安全员 / 巡查员 / 整改责任人 / 机械管理员
- 业务闭环：巡查上报 → 自动判级 → 生成整改任务 → 时限倒计时 → 整改反馈 → 复核销号 → 驾驶舱数字联动
- 方案主线：以「隐患上报 → 自动分级 → 时限倒计时 → 复核销号」为主干，把人员资质、机械维保、进度偏差三类对象挂到同一套预警与闭环机制上。

## 5. 规则体系（口径唯一来源）

规则口径**只在一处定义**，方案规则表、原型展示、代码阈值三处必须同步。改口径先改规则表，再同步另两处。

| # | 规则项 | 对象 | 判定条件 | 处置 |
|---|---|---|---|---|
| 1 | 问题分类 | 全部隐患 | 按性质归入 结构安全类（坍塌 / 触电 / 高处坠落）/ 防护设施类（临边防护缺失 / 机械伤害）/ 文明施工类（其他） | 类别决定责任岗位与处置路径 |
| 2 | 风险分级 | 结构安全类 | 命中即判 | **重大** → 立即停工并上报（0 时限） |
| 3 | 风险分级 | 防护设施类 | 命中即判 | **较大** → 12 小时内完成整改 |
| 4 | 风险分级 | 文明施工类 | 未列明类型 | **一般** → 24 小时内完成整改（兜底分支，不得报错） |
| 5 | 整改督办 | 全部整改工单 | 当前时间晚于整改截止时间 | 已超期 → 触发督办升级 |
| 6 | 资质到期 | 特种作业证件 | 有效期剩余 ≤ 30 天 | 提醒换证 |
| 7 | 资质过期 | 特种作业证件 | 已过有效期 | 禁止上岗（拦截） |
| 8 | 机械维保 | 机械设备 | 距上次维保 > 7 天 | 维保超期 → 停机检修 |
| 9 | 进度偏差 | 施工进度 | 实际对计划偏差 ≥ 15% | 预警（取**绝对值**，超前同样预警） |

**日期比较口径（易错）**：证件有效期、上次维保日等日期型入参统一按**本地自然日 00:00** 比较。用「日期字符串 − 当前时刻」相减会产生小数天，导致「恰好 7 天」被误判为超期。

## 6. 系统设计

### 6.1 原型页面（6 个）

| # | 页面 | 职责 |
|---|---|---|
| 1 | 工程驾驶舱 | 隐患 / 已销号 / 超期 / 待处置 / 重大 / 销号率总览 |
| 2 | 隐患巡查上报 | 上报隐患 → 自动判级 → 生成整改时限 |
| 3 | 隐患整改与销号 | 整改任务卡 + 时限倒计时 + 销号按钮（闭环） |
| 4 | 隐患整改台账 | 全量隐患 + 分级 + 时限 + 状态 |
| 5 | 规则预警中心 | 分级 / 超期 / 证件 / 维保 / 进度五类规则批量跑批 |
| 6 | 安全与进度统计 | 分级分布柱状图 + 超期与预警汇总 |

**驾驶舱卡片**（6 张）：隐患记录 / 已销号 / 超期隐患 / **待处置** / 重大隐患 / 销号率(%)。

**表单字段**：工程名称（与设施台账同名）/ 隐患类型（坍塌·触电·高处坠落·临边防护缺失·机械伤害·文明施工）/ 现场描述 / 上报人·上报单位 / 整改责任人。

**闭环演示路径**：隐患巡查上报（触发判级）→ 隐患整改与销号出现新卡片 → 点销号 → 回驾驶舱看待处置数与统计联动减少。
**闭环判据**：上报后驾驶舱「待处置」卡 +1、销号后 −1 回到初始值；计数不回落即视为闭环未打通。


**原型设计准则**：原型是回答设计问题的可运行演示，详见 `ysy-solution-builder` 的「原型设计准则」一节。本场景原型完成判据：6 页可点通闭环、共享数组联动正确、每条功能需求有对应页面。

### 6.2 核心功能职责

| 功能 | 职责 |
|---|---|
| 问题分类 | 按性质归类并返回类别，决定后续分级分支 |
| 隐患分级判定 | 隐患分级（重大 / 较大 / 一般），含兜底分支 |
| 整改超期督办 | 整改督办超期判定 |
| 证件有效期预警 | 证件状态（正常 / 临期 / 过期） |
| 机械维保预警 | 机械维保超期判定 |
| 进度偏差预警 | 进度偏差预警（取绝对值） |

四层架构：数据层 → 规则引擎 → 接口层 → 演示页。核心功能实现路径（规则表→引擎→接口→页面）见 `ysy-solution-builder` §13。**接口层必须被真实调用**——演示页所有操作走接口层，不得直连引擎，否则四层架构没有打通。

### 6.3 数据模型

四类样例数据：隐患 / 证件 / 机械 / 进度（内存数组，与规则表同口径）。

## 8. 交付框架与验收标准

本场景按跨场景交付框架产出 **5 类交付物**（详见 `ysy-solution-builder` 第 6 节），场景特有口径如下：

| # | 交付物 | 本场景验收要点 |
|---|---|---|
| 1 | 需求分析文档 | 七章齐全（项目概述 / 角色与场景 / 痛点 / 功能需求 / 数据需求 / 非功能需求 / 需求来源）+ 4 表；另存 HTML 美化版 |
| 2 | 数字化解决方案 | 九章齐全（方案总述 / 痛点 / 业务闭环 / 角色职责 / 规则体系 / 功能规划 / 技术架构 / 流程图说明 / 交付物清单）+ 6 表 + HTML 美化版；3 张 vsdx 可解析 |
| 3 | 系统原型 | 6 页可演示，闭环可点通，共享数组联动正确 |
| 4 | 系统核心功能 | 隐患自动分级 + 整改超期督办等判定可运行；规则常量与规则表 7/7 一致、分支全覆盖、边界值正确 |
| 5 | 演示操作清单 | 单页 HTML，逐条列演示动作并追溯到功能需求，覆盖三态（重大 / 较大 / 一般）与超期场景 |


**方案设计次序**：先定规则口径（「规则体系」为唯一来源）→ 再规划功能（每个功能追到规则/需求）→ 最后落页面（原型页面与功能逐条对应）；通用次序见 `ysy-solution-builder`。

## 9. 业务设计要点

1. **本场景按隐患类型单键判级**：无多条件命中；多条件业务「按严重性降序、先判胜出」的通用原则见 `ysy-solution-builder` 第 7 节。
2. **接口层双环境适配**：接口层若依赖脚本级全局量，在浏览器与命令行两种运行环境下行为要一致（浏览器取全局、命令行走模块导入），否则会报未定义变量。
3. **日期口径**：见「规则体系」一节的「日期比较口径」，证件 / 维保类日期判定易在"恰好 N 天"处翻车。

4. **先分类、后分级**：分类是分级的前置，分级阈值只在**同一类别内**比较，跨类比数值会得出错误等级（通用原则见 `ysy-solution-builder` 第 7 节）。
