# ysy-road-transport-safety（道路运输安全监管 · 动态监控与违规闭环处置）

## 1. 本技能做什么

本场景是 7 个场景中最贴近真实监管业务的场景，面向主管部门对辖区「两客一危」重点车辆（客运班车、旅游包车、危险品运输车）的安全监管。核心痛点：**识别靠人工漏报多且分级尺度不统一、工单超期无人督办、屡查屡犯不累计与企业责任难量化**。

本技能给出该场景的业务口径与交付验收标准，供产出需求文档、解决方案、原型、核心功能与演示清单时对照。判定条件可核验、可照抄进代码。

## 2. 何时使用

- 用户要求做「道路运输安全监管」场景的整套交付物；
- 需要该场景的违规识别、风险分级、处置时限、重复违规、企业评价等规则口径与验收基线。

## 3. 需求调研（先做，再定方案）

需求调研是产出需求文档前的主动过程，不是一次问答。按四步推进，每步达成即进入下一步：

1. **角色与场景梳理**——列出本场景全部角色（见「场景定位」）与每个角色的业务动作。
   完成判据：每个角色至少 1 个动作，动作连成业务闭环。
2. **痛点收集**——固定 3 条，每条写成「现象 → 后果」：
   1. 识别靠人工、分级尺度不统一 → 同类违规处置不一，监管口径打折
   2. 工单超期无人督办 → 处置悬空，违规不闭环
   3. 屡查屡犯不累计、企业责任难量化 → 重点企业识别不出，主体责任无法评价
   完成判据：每条痛点至少对应 1 条功能需求。
3. **规则口径确认**——把本场景判定规则逐条钉死（见「规则体系」：**问题分类**（超速类 / 疲劳类 / 线路偏移类）→ **风险分级**（红 30 / 橙 120 / 黄 1440 分钟）、重复违规、企业评价），阈值、时限、边界两侧都明确。
   完成判据：每条规则可判定、可核验，边界两侧（恰好 N / 刚超过 N）都有结果。
4. **需求来源追溯**——每条需求与规则追到来源：业务痛点、引用标准号（写明标准号与条款号）、或题面给定值；自定口径显式标注。
   完成判据：不存在无来源的需求；不编造业务事实与标准号。
   需求分析内容框架与分层追问见 `ysy-solution-builder` §11、§12；开工与收尾门禁、生成前置必答需求调研见 §4、§12（题目口径与预设不同时以用户口径为准）。

## 4. 场景定位

- 系统名：道路运输安全监管平台
- 角色：交通运输主管部门 / 监控值守人员 / 运输企业（管理层）/ 企业安全管理员 / 驾驶员
- 业务闭环：动态监测 → 违规识别 → 预警推送 → 任务处置 → 复核销号 → 统计分析
- 方案主线：以「动态监测 → 违规识别 → 派单处置 → 复核销号」为主干，用分类、分级、时限、重复违规、企业评价五段规则链贯穿。
- 特色能力：**违规分类 + 风险分级 + 处置时限 + 重复违规识别 + 企业评价**五段规则链，更强调可核验性

## 5. 规则体系（口径唯一来源）

| # | 规则项 | 对象 | 判定条件 | 处置 |
|---|---|---|---|---|
| 1 | 问题分类 | 全部告警 | 按违规性质归入 超速类 / 疲劳类 / 线路偏移类 | 类别决定证据要求与推送对象 |
| 2 | 违规类型判定 | 超速行驶 | 速度 > 限速值（普通道路 80 / 高速 100 分档） | 生成告警 + 推送企业 |
| 3 | 违规类型判定 | 疲劳驾驶 | 连续驾驶超 4 小时未停车休息 ≥20 分钟 | 生成告警 + 强制提醒休息 |
| 4 | 违规类型判定 | 线路偏移 | 偏离电子运单线路超过阈值距离（5 km） | 生成告警 + 推送企业核实 |
| 5 | 风险分级 | 高风险（红） | 超速 ≥20% 或疲劳驾驶或 2 次及以上同类违规 | 30 分钟处置 + 监管方督办 |
| 6 | 风险分级 | 中风险（橙） | 单次超速 <20% 或首次线路偏移 | 2 小时处置 + 企业确认 |
| 7 | 风险分级 | 低风险（黄） | 轻微违规、证据待复核 | 24 小时处置 + 值守确认 |
| 8 | 处置时限 | 超期升级 | 超过处置时限未办结 | 升级至监管方 + 企业负责人 |
| 9 | 重复违规 | 屡查屡犯 | 同一车辆/驾驶员 30 天内同类违规 ≥3 次 | 重点监管名单 + 约谈企业 |
| 10 | 企业评价 | 主体责任 | 按违规率、处置及时率、重复违规率加权评价 | 月度评价 + 风险排行 |

**关键常量**：`限速 普通道路=80/高速=100`；`超速红级比例=0.20（超速 ≥20% 判红）`；`疲劳驾驶小时=4`、`疲劳休息分钟=20`；`线路偏移公里=5`；`红级重复次数=2`；`处置时限分钟 高风险=30/中风险=120/低风险=1440`；`临期剩余比=0.2`；`重复违规窗口天=30`、`重复违规次数=3`；`评价权重 违规率0.4/处置及时率0.3/重复违规率0.3`；`评价等级 优秀90/良好75/合格60`。

## 6. 系统设计

### 6.1 原型页面（6 个）

| # | 页面 | 职责 |
|---|---|---|
| 1 | 运行安全总览 | 6 张指标卡 + 实时报警流 |
| 2 | 实时监控 | 车辆列表 + 轨迹状态（在线/离线/超速） |
| 3 | 违规告警 | 报警录入 → 自动识别分级 → 派单 |
| 4 | 处置工单 | 时限倒计时 → 临期提醒 → 超期升级督办 |
| 5 | 复核销号 | 证据核验 → 销号归档 / 驳回重处 |
| 6 | 统计分析 | 违规趋势 + 企业评价排行 + 重复违规清单 |

**驾驶舱卡片**（6 张）：在线车辆 / **高风险违规(红)** / **超期升级督办** / 待处置事件 / 重点监管对象 / 企业平均得分。前三者同取**未销号**口径，首屏即一致。

**表单字段**：车牌号 / 道路类型（**决定限速值**）/ 实测速度 / 连续驾驶时长 / 停车休息时长 / 偏离线路距离 / 窗口内同类违规次数（≥2 次直接判红）。

**闭环演示路径**：违规告警填 130 km/h + 高速 → 判超速 30% → 红级派单 → 工单页出现卡片并倒计时 → 提交处置 → 复核销号通过 → 回总览看待处置数减一、企业平均得分联动。
**闭环判据**：上报后驾驶舱「待处置事件」卡 +1、销号后 −1 回到初始值；计数不回落即视为闭环未打通。


**原型设计准则**：原型是回答设计问题的可运行演示，详见 `ysy-solution-builder` 的「原型设计准则」一节。本场景原型完成判据：6 页可点通闭环、共享数组联动正确、每条功能需求有对应页面。

### 6.2 核心功能职责

| 功能 | 职责 |
|---|---|
| 问题分类 | 按性质归类并返回类别，决定后续分级分支 |
| 违规识别 | 按优先级判类型与初判等级（疲劳 > 超速 ≥20% > 超速 <20% > 偏移） |
| 分级判定 | 输出高/中/低风险与判定依据 |
| 处置时限 | 按等级返回时限分钟数（30 / 120 / 1440） |
| 工单状态 | 时限内／临期·提醒／已超期·升级督办／已办结 |
| 剩余分钟 | 距处置截止的剩余分钟数 |
| 督办处置 | 超期自动升级监管方并留痕 |
| 重复违规识别 | 窗口内同类违规达阈值 → 屡犯标记 |
| 企业评价 | 三项加权总分与等级 |
| 监管统计 | 事件、工单、企业三口径汇总，驾驶舱与统计页同取数 |

四层架构：数据层 → 规则引擎 → 接口层 → 演示页。核心功能实现路径（规则表→引擎→接口→页面）见 `ysy-solution-builder` §13。**接口层必须被真实调用**。

## 9. 业务设计要点

1. **疲劳驾驶优先级最高**：连续 ≥4 小时且休息 <20 分钟**直接判红**，即使速度未超限；先判超速会把它漏成橙甚至无违规。
2. **超速百分比以分档限速为分母**：高速 100 / 普通道路 80；统一按 80 算会把高速 95 误判超速 18.75%（实为无违规），红橙两档错位。
3. **判红有两个入口、阈值不同**：超速 ≥20% **或** 窗口内同类违规 ≥2 次（`红级重复次数=2`），而屡查屡犯用 `重复违规次数=3`——**不可混用**。
4. **时限按等级取**：红 30 / 橙 120 / 黄 1440 分钟；「证据待复核」走低风险 24 小时。
5. **临期按剩余比例判**：剩余 ≤ 时限 × 0.2 才算临期；写成固定 10 分钟，30 分钟工单永不临期。
6. **超期升级 ≠ 自动办结**：超期触发**督办升级**（监管方介入），回传证据后才走复核销号。
7. **首屏三口径同源**：高风险 / 超期 / 待处置 同取**未销号事件**，且待处置数等于工单页卡片数；销号后同步减一。
8. **企业评价三项方向不一致**：违规率、重复违规率越小越好，及时率越大越好；加权前须转正，否则最差企业得分最高。

9. **先分类、后分级**：分类是分级的前置，分级阈值只在**同一类别内**比较，跨类比数值会得出错误等级（通用原则见 `ysy-solution-builder` 第 7 节）。
