# ysy-smart-inspection（智慧试验检测 · 委托受理到报告签发）

## 1. 本技能做什么

面向**试验检测机构 / 工地试验室**。监管链条：委托受理 → 收样派单 → 试验检测 → 判定编制 → 审核签发 → 归档统计。核心痛点是**判定靠人查表、报告超期无人催办、设备与人员资质到期失控**。

本技能给出该场景的业务口径与交付验收标准，供产出需求文档、解决方案、原型、核心功能与演示清单时对照。

## 2. 何时使用

- 用户要求做「智慧试验检测」场景的整套交付物；
- 需要该场景的合格判定、报告超期预警、资质预警等规则口径与验收基线。

## 3. 需求调研（先做，再定方案）

需求调研是产出需求文档前的主动过程，不是一次问答。按四步推进，每步达成即进入下一步：

1. **角色与场景梳理**——列出本场景全部角色（见「场景定位」）与每个角色的业务动作。
   完成判据：每个角色至少 1 个动作，动作连成业务闭环。
2. **痛点收集**——从业务现状归纳真实痛点（判定靠人查表、报告超期无人催办、设备与人员资质到期失控），每条写清「现象 → 后果」。
   完成判据：每条痛点至少对应 1 条功能需求。
3. **规则口径确认**——把本场景判定规则逐条钉死（见「规则体系」：合格判定（≥400 / ≥30 / ≥60 / ≤26）、离群 ±15%、报告 3/4/5/7 工作日、签发 2 工作日、资质 30 天），阈值、时限、边界两侧都明确。
   完成判据：每条规则可判定、可核验，边界两侧（恰好 N / 刚超过 N）都有结果。
4. **需求来源追溯**——每条需求与规则追到来源：业务痛点、引用标准号（写明标准号与条款号）、或题面给定值；自定口径显式标注。
   完成判据：不存在无来源的需求；不编造业务事实与标准号。
   需求分析内容框架与分层追问见 `ysy-solution-builder` §11、§12；开工与收尾门禁、生成前置必答需求调研见 §4、§12（题目口径与预设不同时以用户口径为准）。

## 4. 场景定位

- 系统名：智慧试验检测管理平台
- 角色：委托方 / 受理员 / 试验员 / 报告审核 / 授权签字人 / 质量负责人
- 业务闭环：登记委托 → 自动判定结论 → 生成报告时限 → 不合格触发预警与复检 → 签发销号 → 驾驶舱数字联动
- 特色能力：**数据可信校验**（同组读数离群识别），与「判定结论」共同构成规则体系的两条主线

## 5. 规则体系（口径唯一来源）

| # | 规则项 | 对象 | 判定条件 | 处置 |
|---|---|---|---|---|
| 1 | 合格判定 | 钢筋拉伸强度 | 实测均值 ≥ 400 MPa（HRB400） | 合格 → 自动填结论并流转签发 |
| 2 | 合格判定 | 混凝土试块抗压 | 28d 抗压均值 ≥ 设计等级值（C30 ≥ 30 MPa） | 不合格 → 生成预警 + 复检流程 |
| 3 | 合格判定 | 沥青针入度 | 均值 ≥ 60（0.1 mm） | 合格 → 正常流转 |
| 4 | 合格判定 | 集料压碎值 | 均值 **≤ 26 %**（越小越好，方向为 `≤`） | 超标 → 不合格 + 供应商质量扣分 |
| 5 | 数据可信校验 | 离群读数识别 | 同组读数与均值偏差 **> ±15 %** | 标黄提示 → 复核无果则重测 |
| 6 | 超期预警 | 常规检测报告周期 | 按项目配置 **3 / 4 / 5 / 7 个工作日** | 提前 1 天预警 → 超期升级催办 |
| 7 | 签发时限 | 报告签发 | 试验完成后 **2 个工作日**内签发 | 超期自动催办并升级质量负责人 |
| 8 | 资质预警 | 设备检定 / 人员证书 | 到期前 **30 天**提醒；到期日次日起禁止出具报告 | 提醒办理 → 过期拦截 |

**关键常量**：`偏差限 0.15` / `临期天数 1` / `签发时限 2` / `资质提醒天数 30`。
标准库（4 项）：`HRB400钢筋拉伸 ≥400 MPa 周期5`、`C30混凝土抗压 ≥30 MPa 周期7`、`沥青针入度 ≥60 周期3`、`集料压碎值 ≤26 % 周期4`。

## 6. 系统设计

### 6.1 原型页面（6 个）

| # | 页面 | 职责 |
|---|---|---|
| 1 | 检测驾驶舱 | 委托总量 / 已签发 / 临期超期 / 待处置 / 不合格 / 合格率 |
| 2 | 委托受理 | 登记委托 → 自动判定结论并生成报告时限 |
| 3 | 不合格处置与签发 | 报告倒计时 → 离群/不合格预警 → 签发销号闭环 |
| 4 | 检测任务台账 | 全量委托记录、报告时限与状态 |
| 5 | 规则预警中心 | 规则库批量跑批：合格判定 / 离群复核 / 报告超期 / 资质到期 |
| 6 | 统计与质量分析 | 分项目合格率、不合格与离群预警 |

**驾驶舱卡片**（6 张）：委托总量 / 已签发报告 / 临期超期报告 / **待处置任务** / 不合格结果 / 合格率(%)。其中「待处置任务」是**闭环联动断言的锚点**：上报后 +1、销号后 −1。

**表单字段**：委托单位 / 检测项目（决定标准值与周期）/ 样品编号 / 依据标准 / 实测读数（逗号分隔，≥2 个）。

**闭环演示路径**：委托受理登记（读数填 `398,405,412` 可复现结论）→ 不合格处置与签发出现新任务与倒计时 → 点「签发并销号」→ 回检测驾驶舱看待处置减少、统计页合格率刷新。


**原型设计准则**：原型是回答设计问题的可运行演示，详见 `ysy-solution-builder` 的「原型设计准则」一节。本场景原型完成判据：6 页可点通闭环、共享数组联动正确、每条功能需求有对应页面。

### 6.2 核心功能职责

| 功能 | 职责 |
|---|---|
| 合格判定 | 合格/不合格/跳过，返回均值、离群、判定依据 |
| 离群复核 | 同组读数离散度校验，返回是否需要复核 |
| 剩余工作日 | 距报告到期剩余工作日 |
| 报告状态 | 正常 / 临期·预警 / 已超期·催办 / 已签发 |
| 资质状态 | 正常 / N 天后到期·提醒办理 / 今日到期·立即办理 / 已过期·禁止出具报告 |
| 合格率 | 有效样本、合格、不合格、合格率、不合格明细 |

四层架构：数据层 → 规则引擎 → 接口层 → 演示页。核心功能实现路径（规则表→引擎→接口→页面）见 `ysy-solution-builder` §13。**接口层必须被真实调用**——演示页所有操作走接口层，不得直连引擎。

### 6.3 数据模型

| 表 | 关键字段 |
|---|---|
| 委托任务 | 委托单位 / 检测项目 / 样品号 / 依据 / 收样日 / 读数 |
| 资质 | 编号 / 类型（设备检定·人员证书）/ 名称 / 到期日 |

样例数据主体为浙江本地真实工程（如 S28 台金高速项目部、杭州湾跨海大桥养护项目部等）；依据标准取 GB/T 228.1-2021、GB/T 50081-2019、JTG E20-2011 T0604、JTG E42-2005 T0316。

## 9. 业务设计要点

1. **判定方向必须按项目配置**：压碎值是 `≤ 26`（越小越好），其余是 `≥`。一律用 `≥` 会把压碎值超标判成合格。
2. **有效读数 < 2 应判「跳过」而非「不合格」**，且「跳过」的记录不得计入合格率分母。
3. **时间类判定要支持注入当前时刻**：否则「剩 4.75 天」「剩 −1 天」这类用例无法确定性复现。
4. **边界值按「含等号」判定**：均值恰好等于标准值（如 400）应为**合格**。
5. **离群是相对偏差**：`|读数 − 均值| / 均值 > 0.15`，不是绝对差。
6. **日期型入参按本地自然日 00:00 比较**，避免小数天误判边界日（如「今日到期」）。
