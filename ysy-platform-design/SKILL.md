# ysy-platform-design（数字化管理平台设计 · 流程审批与运行监控）

## 1. 本技能做什么

本场景是 7 个场景中唯一的**平台底座型**（而非单一业务域）设计，面向交通运输行业主管部门 / 机构内部的数字化平台建设。监管链条：统一门户登录 → 业务办理申报 → 流程审批 → 数据集成 → 运行监控 → 安全审计。核心痛点是**事项审批超期无人催、数据同步时效无约束、越权访问无留痕且运行状态无统一视图**。

本技能给出该场景的业务口径与交付验收标准，供产出需求文档、解决方案、原型、核心功能与演示清单时对照。

## 2. 何时使用

- 用户要求做「数字化管理平台设计」场景的整套交付物；
- 需要该场景的审批时限、数据集成 SLA、权限、安全审计等规则口径与验收基线。

## 3. 需求调研（先做，再定方案）

需求调研是产出需求文档前的主动过程，不是一次问答。按四步推进，每步达成即进入下一步：

1. **角色与场景梳理**——列出本场景全部角色（见「场景定位」）与每个角色的业务动作。
   完成判据：每个角色至少 1 个动作，动作连成业务闭环。
2. **痛点收集**——固定 3 条，每条写成「现象 → 后果」：
   1. 事项审批超期无人催 → 办件积压，效能无处考核
   2. 数据同步时效无约束 → 数据新鲜度不可控，一屏统览与实际不一致
   3. 越权访问无留痕、运行状态无统一视图 → 安全隐患不可追溯，运行状况靠人工汇总
   完成判据：每条痛点至少对应 1 条功能需求。
3. **规则口径确认**——把本场景判定规则逐条钉死（见「规则体系」：**问题分类**（审批类 / 集成类 / 权限类 / 审计类）→ **风险分级**（紧急 0 / 重要 1 / 普通 3）、同步 SLA（核心 1h / 一般 24h）、权限矩阵、登录审计），阈值、时限、边界两侧都明确。
   完成判据：每条规则可判定、可核验，边界两侧（恰好 N / 刚超过 N）都有结果。
4. **需求来源追溯**——每条需求与规则追到来源：业务痛点、引用标准号（写明标准号与条款号）、或题面给定值；自定口径显式标注。
   完成判据：不存在无来源的需求；不编造业务事实与标准号。
   需求分析内容框架与分层追问见 `ysy-solution-builder` §11、§12；开工与收尾门禁、生成前置必答需求调研见 §4、§12（题目口径与预设不同时以用户口径为准）。

## 4. 场景定位

- 系统名：数字化管理平台
- 角色：业务办理人员 / 审批人员 / 业务管理员 / 数据分析人员 / 分管领导
- 业务闭环：申报提交 → 按事项级别确定审批时限 → 推送待办 → 时限倒计时 → 超期自动催办升级 → 审批通过办结 → 门户与一屏统览数字联动
- 方案主线：以「统一门户 → 业务申报 → 流程审批 → 办结归档」为主干，用审批时限、集成 SLA、权限、安全审计四条横切能力支撑一屏统览。
- 特色能力：**四条横切能力**（审批时限、数据集成 SLA、RBAC 权限、登录安全审计），共同支撑「一屏统览」

## 5. 规则体系（口径唯一来源）

| # | 规则项 | 对象 | 判定条件 | 处置 |
|---|---|---|---|---|
| 1 | 问题分类 | 全部平台问题 | 按性质归入 审批类 / 集成类 / 权限类 / 审计类 | 类别决定处置责任部门与路径 |
| 2 | 风险分级 | 全部问题 | 阻断业务或涉及安全 → **紧急**；影响时效 → **重要**；仅提醒 → **普通** | 紧急即办（0 天）、重要 1 个工作日、普通 3 个工作日 |
| 3 | 审批时限 | 紧急 / 重要 / 普通 | 紧急即办（**0 天**）、重要 **1 个工作日**、普通 **3 个工作日** | 自动生成待办并推送审批人 |
| 4 | 超期升级 | 审批时限届满 | 届满前 **1 个工作日**提醒；超期自动催办，重要事项升级分管领导 | 超期事项纳入部门效能考核 |
| 5 | 数据集成 | 核心数据源 | 实时同步（**T+0**），**1 小时**内未同步即告警 | 自动告警并通知数据责任人 |
| 6 | 数据集成 | 一般数据源 | 每日批量（**T+1**），**24 小时**内完成同步 | 超时告警，连续超时暂停接口 |
| 7 | 权限管理 | RBAC 角色—数据域 | 授权矩阵内允许访问，**矩阵外一律拦截** | 越权访问拦截并全程留痕 |
| 8 | 安全审计 | 登录行为 | 异常时段（**22:00~06:00**）**或**异地登录触发二次验证 | 两者**同时命中** → 告警 + 二次验证 |
| 9 | 一屏统览 | 平台运行指标 | 待办、超期、同步告警、越权拦截、异常登录**同屏取数** | 驾驶舱与运行月报同口径 |
| 10 | 闭环管理 | 申报—审批—办结 | 申报自动推送审批，办结结果回写业务系统 | 全流程留痕，支持审计追溯 |

**关键常量**：`审批时限 紧急=0、重要=1、普通=3`；`提醒提前天数=1`；`同步SLA 核心=T+0 实时、一般=T+1 批量`；`同步红线小时 核心=1、一般=24`；`关注系数=0.75`；`审计异常时段=[22, 6]`。

## 6. 系统设计

### 6.1 原型页面（6 个）

| # | 页面 | 职责 |
|---|---|---|
| 1 | 平台门户 | 在线数据源 / 超期审批 / 紧急待办 / 待审批事项 / 安全告警 / 同步及时率 |
| 2 | 业务办理 | 统一申报入口 → 按事项级别确定审批时限并推送待办 |
| 3 | 流程审批 | 时限倒计时 → 超期自动催办/升级 → 审批通过办结闭环 |
| 4 | 数据集成台账 | 数据源、同步方向、SLA 时效与同步状态 |
| 5 | 安全审计与规则预警 | 规则库批量跑批：审批时限 / 异常登录 / 同步超时 |
| 6 | 一屏统览 | 按级别统计待办／已办、超期审批与安全告警 |

**驾驶舱卡片**（6 张）：在线数据源 / **超期审批** / 紧急待办 / 待审批事项 / 安全告警 / 同步及时率(%)。

**表单字段**：事项名称 / 事项级别（**决定审批时限**：普通·重要·紧急）/ 申报单位·机构 / 申报人 / 申报人角色（用于**权限校验**）。

**闭环演示路径**：业务办理提交申报（级别选「紧急」可复现即办与超时升级，选「普通」复现 3 个工作日时限）→ 流程审批出现新增待办与时限倒计时 → 点「审批通过并办结」→ 回平台门户看数字联动、一屏统览待办/已办刷新。
**闭环判据**：上报后驾驶舱「待审批事项」卡 +1、销号后 −1 回到初始值；计数不回落即视为闭环未打通。


**原型设计准则**：原型是回答设计问题的可运行演示，详见 `ysy-solution-builder` 的「原型设计准则」一节。本场景原型完成判据：6 页可点通闭环、共享数组联动正确、每条功能需求有对应页面。

本场景按跨场景交付框架产出 **5 类交付物**（详见 `ysy-solution-builder` 第 6 节），场景特有口径如下：

| 1 | 需求分析文档 | 七章齐全（项目概述 / 角色与场景 / 痛点 / 功能需求 / 数据需求 / 非功能需求 / 需求来源）+ 4 表；另存 HTML 美化版 |
| 2 | 数字化解决方案 | 九章齐全（方案总述 / 痛点 / 业务闭环 / 角色职责 / 规则体系 / 功能规划 / 技术架构 / 流程图说明 / 交付物清单）+ 6 表 + HTML 美化版；3 张 vsdx 可解析 |
| 3 | 系统原型 | 6 页可演示，闭环可点通，共享数组联动正确 |
| 4 | 系统核心功能 | 审批时限判定 + 数据集成 SLA 监测等判定可运行；审批状态多态、边界值正确 |

**方案设计次序**：先定规则口径（「规则体系」为唯一来源）→ 再规划功能（每个功能追到规则/需求）→ 最后落页面（原型页面与功能逐条对应）；通用次序见 `ysy-solution-builder`。

## 9. 业务设计要点

1. **登录审计的「或 / 且」组合极易写混**：**异常时段 或 异地登录** → 触发二次验证；**两者同时命中** → 额外告警。用「且」做二次验证会漏掉大量单条件异常，用「或」做告警会误报。
2. **异常时段跨零点**：`22:00~06:00` 跨越自然日分界，不能用 `22 <= h && h <= 6`（恒为假），须写成 `h >= 22 || h < 6`。
3. **审批状态是多态而非四态**：至少含「待审批 / 已办结 / 已超期·自动催办」等，不要用布尔 `done` 代替状态机。
4. **紧急事项时限为 0 天**：倒计时应显示「即办」，而非负数天数。
5. **同步红线分两档**：核心源 1 小时、一般源 24 小时，不可共用一个阈值；SLA（T+0/T+1）与红线小时数是**两个独立常量**，不要用 SLA 反推红线。
6. **权限校验默认拒绝**：矩阵外一律拦截（白名单语义），不能写成「矩阵内有权限、其他放行」。
7. **一屏统览必须同口径**：门户卡片与统览页面的取数逻辑要复用同一个统计功能，否则两处数字会不一致。

8. **先分类、后分级**：分类是分级的前置，分级阈值只在**同一类别内**比较，跨类比数值会得出错误等级（通用原则见 `ysy-solution-builder` 第 7 节）。
