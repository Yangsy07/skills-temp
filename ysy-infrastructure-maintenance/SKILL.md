# ysy-infrastructure-maintenance（交通基础设施养护 · 病害分级与养护工单）

## 1. 本技能做什么

面向**桥隧与路面设施**的日常养护管理。监管链条：日常巡查 → 病害上报 → 自动分级 → 生成养护工单 → 按级倒计时 → 处置反馈 → 复核销号 → 技术状况评定。核心痛点是**病害定级靠经验、处置时限靠记忆、巡查频次靠自觉**。

本技能给出该场景的业务口径与交付验收标准，供产出需求文档、解决方案、原型、核心功能与演示清单时对照。

## 2. 何时使用

- 用户要求做「交通基础设施养护」场景的整套交付物；
- 需要该场景的病害分级、处置时限、巡查频次、技术状况评定等规则口径与验收基线。

## 3. 需求调研（先做，再定方案）

需求调研是产出需求文档前的主动过程，不是一次问答。按四步推进，每步达成即进入下一步：

1. **角色与场景梳理**——列出本场景全部角色（见「场景定位」）与每个角色的业务动作。
   完成判据：每个角色至少 1 个动作，动作连成业务闭环。
2. **痛点收集**——从业务现状归纳真实痛点（病害定级靠经验、处置时限靠记忆、巡查频次靠自觉），每条写清「现象 → 后果」。
   完成判据：每条痛点至少对应 1 条功能需求。
3. **规则口径确认**——把本场景判定规则逐条钉死（见「规则体系」：病害分级（裂缝 0.1/0.2 mm、坑槽 2 ㎡、剥落 1 ㎡）、处置时限 Ⅲ0/Ⅱ15/Ⅰ30、巡查周期、PCI 分级），阈值、时限、边界两侧都明确。
   完成判据：每条规则可判定、可核验，边界两侧（恰好 N / 刚超过 N）都有结果。
4. **需求来源追溯**——每条需求与规则追到来源：业务痛点、引用标准号（写明标准号与条款号）、或题面给定值；自定口径显式标注。
   完成判据：不存在无来源的需求；不编造业务事实与标准号。
   需求分析内容框架与分层追问见 `ysy-solution-builder` §11、§12；开工与收尾门禁、生成前置必答需求调研见 §4、§12（题目口径与预设不同时以用户口径为准）。

## 4. 场景定位

- 系统名：交通基础设施智慧管养平台
- 角色：巡查员 / 养护管理人员 / 养护作业单位 / 桥隧工程师 / 主管部门领导
- 业务闭环：巡查上报 → 自动定级（Ⅰ/Ⅱ/Ⅲ）→ 定级决定处置时限 → 生成工单并倒计时 → 处置完成销号 → 驾驶舱与分级分布联动
- 特色能力：三套并行的分级规则（**病害分级 / 处置时限 / 巡查频次**）＋ PCI 技术状况评定

## 5. 规则体系（口径唯一来源）

| # | 规则项 | 对象 | 判定条件 | 处置 |
|---|---|---|---|---|
| 1 | 病害分级 | 裂缝类 | 宽度 ≥0.1 mm → Ⅱ 类；**≥0.2 mm → Ⅲ 类** | 自动定级，等级决定处置时限 |
| 2 | 病害分级 | 坑槽 / 剥落 | 坑槽面积 >2 ㎡、剥落面积 >1 ㎡ → Ⅱ 类 | 自动定级；未达阈值 → Ⅰ 类纳入年度养护计划 |
| 3 | 病害分级 | 渗水 / 结构变形 | 定性判定 → **直接 Ⅲ 类** | 立即处置 + 限制通行 + 上报 |
| 4 | 处置时限 | Ⅲ / Ⅱ / Ⅰ 类 | Ⅲ 类立即处置（**0 天**）、Ⅱ 类 **15 天**、Ⅰ 类 **30 天**（自然日） | 自动生成养护工单并按级倒计时 |
| 5 | 超期预警 | 养护工单时限 | 时限届满前 **1 天**预警；超期自动升级 | 升级至养护主管并纳入月度考核 |
| 6 | 巡查频次 | 特大桥 / 大桥 / 中桥 / 隧道 | 特大桥 **每日**、大桥 **每周**、中桥与隧道 **每月** | 逾期未巡自动预警并推送巡查员 |
| 7 | 技术状况评定 | 路面 PCI | ≥85 优、70~85 良、55~70 中、**<55 差** | 评为「差」的优先纳入大中修计划 |
| 8 | 统计决策 | 分级分布与优良率 | 按病害类型统计 Ⅰ/Ⅱ/Ⅲ 分布，按设施统计 PCI 优良率 | 支撑年度养护计划与考核编制 |

**关键常量**：`裂缝Ⅱ=0.1` / `裂缝Ⅲ=0.2` / `坑槽Ⅱ=2` / `剥落Ⅱ=1`；`时限 Ⅰ=30、Ⅱ=15、Ⅲ=0`；`PCI 优=85、良=70、中=55`；`巡查周期 特大桥=1、大桥=7、中桥=30、隧道=30`；`预警提前天数=1`。

## 6. 系统设计

### 6.1 原型页面（6 个）

| # | 页面 | 职责 |
|---|---|---|
| 1 | 管养驾驶舱 | 设施数 / 病害数 / 紧急病害 / 待处置工单 / 超期工单 / PCI 优良率 |
| 2 | 日常巡查上报 | 巡查发现病害 → 自动分级并确定处置时限、生成养护工单 |
| 3 | 养护工单处置 | 按分级时限倒计时 → 处置反馈 → 复核销号闭环 |
| 4 | 设施建档台账 | 一设施一档：技术状况等级、最近巡查、巡查周期 |
| 5 | 病害分级与预警 | 分级规则批量跑批：病害分级 / 处置时限 / 巡查逾期 |
| 6 | 统计与决策 | 病害类型与分级分布、紧急与超期预警 |

**驾驶舱卡片**（6 张）：在册设施 / 病害记录 / Ⅲ类紧急病害 / **待处置工单** / 超期工单 / PCI 优良率(%)。

**表单字段**：设施（与台账同名）/ 病害类型（裂缝·坑槽·剥落·渗水·结构变形）/ 量化指标（裂缝宽度 mm 或坑槽·剥落面积 ㎡）/ 巡查人·巡查单位 / 现场描述。

**闭环演示路径**：日常巡查上报（裂缝填 `0.25` 可复现 Ⅲ 类紧急，填 `0.05` 复现 Ⅰ 类）→ 养护工单出现新工单与处置倒计时 → 点「处置完成并销号」→ 回管养驾驶舱看数字联动、统计决策分级分布刷新。


**原型设计准则**：原型是回答设计问题的可运行演示，详见 `ysy-solution-builder` 的「原型设计准则」一节。本场景原型完成判据：6 页可点通闭环、共享数组联动正确、每条功能需求有对应页面。

| 功能 | 职责 |
|---|---|
| 病害分级 | 病害定级 Ⅰ/Ⅱ/Ⅲ，按病害类型走不同量纲分支 |
| 处置时限 | 按等级返回处置时限天数（Ⅲ 类为 0） |
| 处置说明 | 返回该等级对应的处置动作文字 |

## 9. 业务设计要点

1. **分级阈值重叠，必须按严重性降序判定**：0.20 mm 同时满足「≥0.1 → Ⅱ」与「≥0.2 → Ⅲ」。按升序先判会把 Ⅲ 类紧急病害降级为 Ⅱ 类，处置时限从「立即」错成 15 天。
2. **量化指标字段承载两种量纲**：裂缝是宽度（mm），坑槽/剥落是面积（㎡）。判定分支必须**先按病害类型分流**，不能拿同一个阈值比。
3. **Ⅲ 类时限为 0 天**：倒计时需显示为「立即处置」而非「超期 0 天」。
4. **PCI 边界含等号**：`≥85` 优、`70~85` 良——85 归「优」、70 归「良」，用 `>` 会把边界错判一档。
5. **巡查周期由设施类型带出**：表单只填设施名，周期需回台账查类型再映射，不能默认一个值。
6. **「渗水 / 结构变形」是定性判定直接 Ⅲ 类**，不参与量化阈值比较，分支顺序应放在量化判定之前。
