# ysy-data-analysis（检测数据分析 · 数据治理与供应商评级）

## 1. 本技能做什么

面向**多源检测数据的汇聚治理与分析**。监管链条：数据接入 → 清洗校验 → 异常识别 → 人工复核 → 入库销号 → 统计报表 → 供应商评级。核心痛点是**数据源口径不一且脏数据直接入账、异常读数无人复核、供应商质量无量化评价**。

本技能给出该场景的业务口径与交付验收标准，供产出需求文档、解决方案、原型、核心功能与演示清单时对照。

## 2. 何时使用

- 用户要求做「检测数据分析」场景的整套交付物；
- 需要该场景的四类异常识别口径、供应商评级、趋势预警等规则口径与验收基线。

## 3. 需求调研（先做，再定方案）

需求调研是产出需求文档前的主动过程，不是一次问答。按四步推进，每步达成即进入下一步：

1. **角色与场景梳理**——列出本场景全部角色（见「场景定位」）与每个角色的业务动作。
   完成判据：每个角色至少 1 个动作，动作连成业务闭环。
2. **痛点收集**——固定 3 条，每条写成「现象 → 后果」：
   1. 数据源口径不一、脏数据混入 → 台账数据不可信，统计结论失真
   2. 异常读数无人复核 → 异常直接流入报表，质量判定与评级失真
   3. 供应商质量无量化评价 → 采购与准入缺依据，问题供应商反复中标
   完成判据：每条痛点至少对应 1 条功能需求。
3. **规则口径确认**——把本场景判定规则逐条钉死（见「规则体系」：**问题分类**（离群类 / 缺失类 / 突变类）→ **风险分级**（重大 / 较大 / 一般）、3σ 离群、偏差 ±15%、缺失率 5%、环比 50%、评级 A95/B90），阈值、时限、边界两侧都明确。
   完成判据：每条规则可判定、可核验，边界两侧（恰好 N / 刚超过 N）都有结果。
4. **需求来源追溯**——每条需求与规则追到来源：业务痛点、引用标准号（写明标准号与条款号）、或题面给定值；自定口径显式标注。
   完成判据：不存在无来源的需求；不编造业务事实与标准号。
   需求分析内容框架与分层追问见 `ysy-solution-builder` §11、§12；开工与收尾门禁、生成前置必答需求调研见 §4、§12（题目口径与预设不同时以用户口径为准）。

## 4. 场景定位

- 系统名：检测数据治理与分析平台
- 角色：数据源单位 / 数据分析师 / 业务部门 / 质量监督部门 / 行业主管部门 / 机构与供应商
- 业务闭环：接入数据 → 自动清洗（缺失剔除）→ 异常识别（4 类判据）→ 生成待复核任务 → 复核标记销号 → 驾驶舱与报表联动
- 方案主线：以「数据接入 → 清洗校验 → 异常识别 → 复核销号」为主干，四类异常判据并行，出口落到供应商评级与趋势预警。
- 特色能力：**四类异常判据并行**（3σ 离群 / 偏差限 / 缺失率 / 环比突变）＋ 供应商合格率 A/B/C 评级

## 5. 规则体系（口径唯一来源）

| # | 规则项 | 对象 | 判定条件 | 处置 |
|---|---|---|---|---|
| 1 | 问题分类 | 全部异常 | 按性质归入 离群类（3σ / 偏差限）/ 缺失类 / 突变类 | 类别决定复核责任人与回查方向 |
| 2 | 风险分级 | 全部异常 | 离群已流入合格判定 → **重大**；偏差限离群、环比突变 → **较大**；缺失率超线、待复核 → **一般** | 重大立即复核并暂停该源入库；较大当日复核；一般按周处置 |
| 3 | 数据清洗 | 有效读数识别 | 空值 / 非数值 / **≤0** 一律视为缺失并剔除 | 缺失读数不计入均值与标准差 |
| 4 | 异常识别 | 3σ 离群 | 与历史基线偏差 **> 3σ**（μ、σ 取历史基线） | 标红复核，复核无果则重测 |
| 5 | 异常识别 | 偏差限 | 无基线时，与同组均值偏差 **> ±15 %** | 人工复核并回查原始记录 |
| 6 | 异常识别 | 缺失率红线 | 单源单期缺失率 **> 5 %** | 回查数据源，必要时暂停该源数据入库 |
| 7 | 异常识别 | 环比突变 | 本期均值与上期偏差 **> 50 %** | 核对检测口径与样品对应关系 |
| 8 | 数据分析 | 合格判定 | 均值 ≥ 标准库标准值 → 合格 | 不合格进入不合格品处置流程 |
| 9 | 供应商评价 | 合格率评级 | **≥95 % A 级 / 90~95 % B 级 / <90 % C 级** | C 级触发约谈与限期整改 |
| 10 | 趋势预警 | 连续下滑 | 连续 **3 期**合格率下降 | 自动预警并推送质量负责人 |

**关键常量**：`sigma=3` / `devRatio=0.15` / `missingRate=0.05` / `jumpRatio=0.5`；`passStd 钢筋HRB400=400、混凝土C30=30、沥青混合料AC-13=60`；`grade A=0.95、B=0.9`。

## 6. 系统设计

### 6.1 原型页面（6 个）

| # | 页面 | 职责 |
|---|---|---|
| 1 | 数据驾驶舱 | 接入记录 / 已复核 / 异常记录 / 待复核 / 清洗通过率 / 数据合格率 |
| 2 | 数据接入与清洗 | 多源数据接入 → 自动清洗校验与异常识别 → 生成待复核任务 |
| 3 | 异常复核 | 逐条复核判据（3σ／偏差／缺失／突变）→ 标记或入库销号闭环 |
| 4 | 数据台账 | 全量接入记录：有效读数、缺失率、均值、合格判定、评级 |
| 5 | 规则预警中心 | 规则库批量跑批：3σ 离群 / 偏差限 / 缺失率 / 环比突变 |
| 6 | 统计与报表 | 分项目合格率与评级、异常明细预警 |

**驾驶舱卡片**（6 张）：接入记录 / 已复核入库 / 异常记录 / **待复核记录** / 清洗通过率(%) / 数据合格率(%)。

**表单字段**：数据源（自动化试验设备直连·检测机构LIMS系统·移动端人工录入·第三方监测平台）/ 检测项目（决定标准阈值）/ 样品编号 / 实测读数（逗号分隔，**缺失值填「空」**）/ 上期均值（用于环比突变识别，可留空）。

**闭环演示路径**：数据接入与清洗登记一批读数（钢筋填 `430,432,428,431` 可复现 3σ 离群；某项填「空」可复现缺失率预警）→ 异常复核看到新增任务与判据 → 点「复核异常并标记」→ 回数据驾驶舱看数字联动、统计与报表合格率刷新。
**闭环判据**：上报后驾驶舱「待复核记录」卡 +1、销号后 −1 回到初始值；计数不回落即视为闭环未打通。


**原型设计准则**：原型是回答设计问题的可运行演示，详见 `ysy-solution-builder` 的「原型设计准则」一节。本场景原型完成判据：6 页可点通闭环、共享数组联动正确、每条功能需求有对应页面。

### 6.2 核心功能职责

| 功能 | 职责 |
|---|---|
| 问题分类 | 按性质归类并返回类别，决定后续分级分支 |
| 有效读数 | 剔除空值/非数值/≤0，返回有效读数集 |
| 均值 | 有效读数均值 |

| 趋势预警 | 连续下滑判定 |
| 数据质量统计 | 接入量、清洗通过率、合格率等汇总 |

## 9. 业务设计要点

1. **σ=0 必须退化，不得除零**（本场景最隐蔽的坑）。3σ 分支的前置条件是**历史基线存在且 σ > 0**；当基线缺失或 σ=0（例如同组读数全相同）时，自动**退化到「同组偏差限 ±15 %」分支**。若直接做 `(x−μ)/σ` 会得到 `NaN`/`Infinity`，异常识别静默失效。
2. **有效读数剔除规则是「空值 / 非数值 / ≤0」三类**，不是仅空值。手填 `0` 会被当作缺失剔除，不能计入均值。
3. **缺失率与异常是两个独立维度**：缺失率高（>5 %）不代表读数异常，两者要分别出结论，不能合并成一个「数据有问题」。
4. **环比突变需要「上期均值」入参**，可留空；留空时应跳过该判据而非判为突变。
5. **评级边界含等号**：`≥0.95` A、`≥0.90` B、其余 C——恰好 95 % 归 A，恰好 90 % 归 B。
6. **趋势预警需连续 3 期**，单期下滑不触发；实现时要有历史序列入参，不能只看当前一期。

7. **先分类、后分级**：分类是分级的前置，分级阈值只在**同一类别内**比较，跨类比数值会得出错误等级（通用原则见 `ysy-solution-builder` 第 7 节）。
